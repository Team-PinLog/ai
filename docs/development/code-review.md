# AI 코드 리뷰 가이드

운영 기준은 [`CONTRIBUTING.md`](../../CONTRIBUTING.md), 개발 순서는
[`workflow.md`](workflow.md)를 따른다.

## 리뷰 우선순위

1. **정확성**: 요구사항과 실패·경계·동시성 경로가 올바른가
2. **테스트**: 변경 의도를 증명하며 외부 호출 횟수와 DB 계약을 검증하는가
3. **계약**: API, 상태 전이, 데이터 및 공용 AI 계약을 지키는가
4. **보안·개인정보**: 비밀값과 개인 데이터가 코드, 로그, PR에 노출되지 않는가
5. **유지보수성**: 불필요한 계층·의존성·예측 구현 없이 이해 가능한가
6. **범위**: Jira와 PR이 선언한 작업만 포함하는가

스키마 변경은 백엔드 V100–V199 migration과 AI
`tests/schema/ai_snapshot.sql`의 연결된 티켓·PR이 있는지 확인한다.

## 의견 작성과 응답

- 차단 의견은 문제, 영향, 재현 조건 또는 근거를 함께 적는다.
- 선택 제안은 `nit:`으로 표시해 필수 수정과 구분한다.
- 취향보다 계약, 정확성, 보안과 검증 가능한 근거를 우선한다.
- 작성자는 각 의견에 변경 내용 또는 변경하지 않은 이유를 답한다.
- 규칙 자체가 바뀌었다면 코드뿐 아니라 기준 문서도 함께 고친다.

모든 대화는 병합 전에 해결한다. 해결 표시는 작성자와 리뷰어의 합의로 수행한다.
미해결 의견을 남긴 채 병합하지 않으며, 병합 후 리뷰를 정상 절차로 사용하지 않는다.

## 담당 경계

- AI 계약·scoring 정책·개인정보 경계: AI 파트
- Feed 런타임 구현·테스트: 백엔드 파트 (`back` 레포)
- Spring·DB·트랜잭션·캐시·백엔드 테스트: 백엔드 담당자

교차 계약 PR은 Draft 단계에서 관련 담당자를 모두 reviewer로 지정한다. 필수
승인 수가 0인 설정은 리뷰가 불필요하다는 뜻이 아니다. 실제 검토 증거는 PR
대화와 Jira에 남긴다.

## 병합 체크리스트

- [ ] Jira 키와 PR 범위가 일치한다.
- [ ] RED/GREEN/Regression 증거가 재현 가능하다.
- [ ] 계약, 보안·개인정보, 실패 경로를 확인했다.
- [ ] 모든 리뷰 대화가 해결됐다.
- [ ] 범위 밖 작업은 후속 Jira로 분리됐다.
- [ ] 필요한 영구 문서와 WORKLOG가 갱신됐다.
