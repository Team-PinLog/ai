`S15P11A705-210` 후보 유사도 임계값 측정 중 겪은 것. 결과 리포트는
[구현 리포트](../implements/2026-07-31-candidate-threshold.md)에 있다.

## T37 — 「임계값이 없다」는 진단이 틀렸다. 임계값은 처음부터 있었다

**상태: 해결됨(진단 정정)**

### 증상

티켓과 계약이 원인을 이렇게 적었다.

> top-10 에 임계값이 없어 무관한 입력에도 후보 10개가 채워지고, LLM 은 「이 중에서
> 골라라」를 받아 「가지튀김이 미쳤음 → 술자리」 같은 답을 낸다

작업은 「`similarity >= τ` 조건 하나와 설정 주입」으로 잡혀 있었다.

### 실제

`app/service/keyword_service.py` 의 `_topk` 는 처음부터 하한을 걸고 있었다.

```python
order = np.argsort(-sims)[:k]
return [presets[i] for i in order if sims[i] >= floor]
```

설정도 주입되어 있고(`SIMILARITY_FLOOR=0.30`, `config.py:114`) 테스트도 둘 있었다.

```
tests/test_unit.py::test_topk_excludes_below_floor
tests/test_pipeline.py::test_no_candidate_above_floor_completes_without_calling_llm
```

「후보 10개가 채워진다」도 사실이 아니다. **실측 후보는 평균 7.4개**로, 0.30 이 프리셋
27개 중 19.6개를 이미 걸러내고 있었다.

### 왜 이렇게 보였나

증상은 실재했다. 「가지튀김이 미쳤음」에 `DRINK 술자리`가 붙는 것은 진짜다. **증상에서
원인을 역산할 때 「임계값이 없어서」가 가장 그럴듯했고, 그 가설로 코드를 열지 않았다.**

실제 원인은 임계값의 부재가 아니라 **적합/부적합의 유사도 분포가 겹친다**는 것이다.
부적합 판정의 최댓값(0.4225) 아래에 적합 판정이 34/63건 있다. 임계값을 어디에 두든
둘을 함께 자른다.

### 다음 사람에게

**「기능이 없어서 그렇다」는 진단은 그 기능을 grep 해 보고 쓴다.** 한 줄이면 끝난다.

```bash
grep -rn "similarity_floor\|SIMILARITY_FLOOR" app/ tests/
```

이 경우 티켓의 나머지(τ 를 근거로 정하라)는 그대로 유효했다. 전제가 틀렸다고 티켓이
무효가 되는 것은 아니고, **틀린 전제 위에 세운 작업 계획만 무효**다. 「조건을 넣는다」가
「이미 있는 값을 실데이터로 재검증한다」로 바뀐다.

## T38 — 스크립트에만 인코딩 방어를 넣으면 탐색용 한 줄에서 같은 문제를 다시 겪는다

**상태: 해결됨**

### 증상

`tools/tau_grid/*.py` 는 전부 [T28](2026-07-30-seeding-quota-and-encoding.md) 대로
`sys.stdout.reconfigure(encoding="utf-8")` 를 넣어 두었다. 그런데 분포를 빠르게 보려고
쓴 `python -c` 한 줄이 예외로 중단됐다.

```
UnicodeEncodeError: 'cp949' codec can't encode character '—'
```

**출력 앞부분은 이미 찍힌 뒤였다.** 숫자 네 줄이 나오고 다섯 번째 줄에서 중단돼서, 처음엔
계산이 끝난 줄 알고 그 네 줄을 읽었다. 찍힌 것도 한글이 깨져 있었다.

### 원인

`-c` 로 넘긴 코드에는 그 방어가 없다. T28 은 「스크립트가 stdout 을 스스로 재구성한다」로
해결됐고 그래서 **호출자가 `PYTHONIOENCODING` 을 기억할 필요가 없어졌는데**, 그 면제가
스크립트 밖으로는 따라오지 않는다.

### 해결

탐색용 한 줄에는 환경변수를 붙인다.

```bash
PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -c "..."
```

여러 번 돌릴 것이면 파일로 옮긴다. 파일이면 방어가 코드에 들어가고 재현도 된다.

## T39 — 재판정 차이를 대조군 없이 읽으면 전부 τ 탓이 된다

**상태: 해결됨(측정 설계)**

### 증상

τ 를 바꿔 재판정하면 결과가 달라진다. 그 차이를 τ 의 효과로 읽고 싶어진다.

### 실제

**같은 τ 로 다시 판정만 해도 Context 11/42(26%)에서 결과가 달라진다.** 대조군
(τ=0.30 을 그대로 재판정)과 본실험(τ=0.34)의 어긋남이 **둘 다 11/42** 였다.

데이터가 같은 것을 한 번 더 보여줬다. 42건 중 5쌍이 같은 본문인데(생성분이 기존 본문을
복제), **3쌍의 판정이 달랐다.** 본문이 같으면 벡터도 후보도 같으므로 순수한 재현성 측정이 된다.

```
268/293   MEAL          vs  MEAL + CELEBRATION
270/292   COZY          vs  TRENDY
275/290   —             vs  VIEW_GOOD
```

### 다음 사람에게

**판정(LLM) 계층을 건드리는 측정은 대조군을 같이 돌린다.** 비용이 두 배가 되지만
대조군이 없으면 「효과 있음」과 「그날 그렇게 나왔음」을 가를 수 없다.

이 티켓에서는 그 비교가 결론을 바꿨다. τ 를 0.30→0.34 로 올려 얻는 효과가
비결정성이 만드는 변동과 **같은 크기**라는 것이 τ 상향을 기각하는 근거 하나가 됐다.

임베딩은 결정적이므로 이 대조군이 필요 없다(`emb_grid` 가 검색 순위를 2회 실행에서
동일하게 재현한 것이 그 예다). **비결정적인 것은 판정뿐이다.**
