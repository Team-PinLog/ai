## T40. 반대 방향 질의를 재지 않으면 컷의 절반이 안 보인다

`demo_data.yaml` 의 검증 질의 12건은 **전부 기대 정답을 가진다.** 그것만으로 격자를
훑으면 이런 표가 나온다.

```
r 단독      정답 누락 0/12 · 빈 결과 0/12 · 꼬리 제거 97.4%   ← r 이 압도적으로 보인다
τ_abs 단독  정답 누락 0/12 · 빈 결과 0/12 · 꼬리 제거 87.7%
조합        τ_abs 를 어떤 값으로 두든 r=0.80 과 결과가 같다   ← τ_abs 가 불필요해 보인다
```

여기서 멈췄으면 **「`r` 하나면 된다」가 결론**이었을 것이다. 실제로 조합 격자 상위 12개가
전부 `r=0.80` 이었고 `τ_abs` 값에 무관하게 같은 수치였다.

### 실제

`r` 은 정의상 **1위를 언제나 남긴다**(`sim ≥ r × top1` 에서 1위는 `r=1.0`). 즉 「이
사용자에게 관련 기록이 하나도 없다」를 0건으로 표현할 수 없다. 정답이 없는 무관 질의
15건을 추가하자 그 열이 이렇게 나왔다.

```
r = 0.40 … 0.90   무관 질의 15건 중 0건이 된 것:  0/15   (모든 값에서)
τ_abs = 0.34      무관 질의 15건 중 0건이 된 것: 14/15
```

**`r` 이 아무것도 못 하는 축이 있다.** 그 축은 정답이 있는 질의만 재면 존재 자체가
드러나지 않는다.

### 다음 사람에게

**컷·필터·임계값을 재려면 「걸러져야 하는 입력」을 표본에 넣는다.** 통과해야 하는 것만
모아 두면 「덜 자르는 쪽」이 언제나 이기고, 그것은 컷을 재는 것이 아니라 컷을 끄는 쪽으로
기우는 측정이다.

같은 이유로 「0건」의 부호가 축마다 반대라는 것도 표에서 갈라야 한다 — 검증 질의의 0건은
최악이고 무관 질의의 0건은 최선이다. 한 표에 섞으면 컷을 반대로 읽는다.

## T41. worktree 에는 `.env` 가 없다 — `get_settings()` 가 그 자리에서 죽는다

`git worktree` 로 격리해 측정 스크립트를 돌리면 첫 줄에서 이렇게 죽는다.

```
pydantic_core._pydantic_core.ValidationError: 5 validation errors for Settings
  GMS_API_KEY  Field required
  ...
```

`Settings.model_config` 의 `env_file=".env"` 는 **CWD 기준**이고 `.env` 는 gitignore 라
worktree 에 존재하지 않는다. `-191` 이 겪은 「worktree 에서 실행하면 데모 JWT 키가 새로
생긴다」(`.demo/` 가 gitignore)와 **같은 원인의 다른 증상**이다.

```bash
cp ai/.env ai/.claude/worktrees/<name>/.env
DATABASE_URL="postgresql://…:15432/pinlog" .venv/Scripts/python.exe tools/…
```

`.env` 의 `DATABASE_URL` 은 07-27 잔재인 `:5433` 이므로 복사한 뒤에도 환경변수로
덮어써야 한다(T33). 환경변수가 `.env` 보다 우선한다.

### 다음 사람에게

**gitignore 된 것은 worktree 에 없다.** `.env`·`.demo/`·`.venv/` 가 전부 그렇다.
worktree 격리는 **커밋되는 것만** 복제한다.

`.venv` 는 메인 것을 절대경로로 부르면 된다 — `sys.path.insert(ROOT)` 가 worktree 를
앞에 넣으므로 **코드는 worktree 것, 인터프리터는 메인 것**이 된다. 그것이 의도한 조합이다.

## T42. 임베딩은 결정적이지만 **배치 구성이 바뀌면** 소수 넷째 자리가 흔들린다

무관 질의 5건을 추가하며 임베딩 배치가 12건에서 17건이 됐다. 기존 12건의 텍스트는
한 글자도 바꾸지 않았는데 유사도가 달라졌다.

```
치킨버거 이스트사이드 (「밥 먹고 산책하면서 쉬어가는 공원」)   0.5264 → 0.5258
irrelevant 최댓값                                        0.4489 → 0.4488
plausible 최댓값                                         0.5264 → 0.5258
```

순위는 하나도 바뀌지 않았고 결론도 그대로다. 다만 `-191` 이 「임베딩이 결정적이라 실패
2건의 유사도가 소수 넷째 자리까지 일치한다」고 적은 것은 **같은 배치 구성으로 다시 돌렸을
때**의 이야기다. `emb_grid` 는 조건마다 같은 순서로 같은 텍스트를 보냈으므로 그 전제가
성립했다.

### 다음 사람에게

**`10⁻⁴` 규모 차이가 채택 여부를 가르는 값은 쓰지 않는다.** 이 티켓에서 안전 상한
(`τ_abs=0.36`·`r=0.80`)에 붙이지 않고 마진을 둔 이유 중 하나가 이것이다 — 상한과 정답
최솟값의 거리가 `0.0042` 였는데, 그것은 배치 구성만 바뀌어도 넘어갈 수 있는 폭이다.

임베딩 결과를 커밋해 둔 이유이기도 하다(`.search/matrix.json`). 다시 뜨면 미세하게
다른 값이 나오므로, **문서에 적힌 수치를 재현하려면 그때의 행렬이 있어야 한다.**
